Labs & Vulnerabilities Cases

Interactive demonstrations, video walkthroughs, and security reflections.

Case 1 Login Test

Authentication & Login Vulnerability

Demonstration of broken authentication mechanisms in login workflows and implementation of secure credential hashing with rate limiting.

Reflection:

[2–3 SENTENCES: Reflected on the critical impact of improper session management. Implementing multi-factor authentication and enforced salted passwords greatly mitigates credential stuffing attacks.]

Case 2 Data Security 1

Insecure Local Data Storage

Analyzing unencrypted local storage vulnerability on client devices and fixing it using Room with SQLCipher integration.

Reflection:

[2–3 SENTENCES: Storing user tokens in plain text poses severe risk if physical device access is compromised. Encrypted Shared Preferences and hardware-backed keystores are non-negotiable.]

View on GitHub
Case 3 Data Security 2

Insecure Transit & API Data Leakage

Intercepting unencrypted HTTP traffic via Proxy tools and securing data transmission using Retrofit SSL Pinning.

Reflection:

[2–3 SENTENCES: Man-in-the-middle attacks highlight why TLS is not enough on its own. Implementing certificate pinning guarantees that client apps communicate exclusively with authentic backends.]

View on GitHub
Case 4 Injection Attack

SQL Injection Remediation

Simulating SQL Injection in query inputs and patching it with parameterized queries and ORM object mappers.

Reflection:

[2–3 SENTENCES: Dynamic query string concatenation remains a primary cause of database breaches. Adopting prepared statements completely isolates executable commands from user input data.]

View on GitHub
Case 5 CameraX / ML Integration

Biometric & Camera Permission Leak

Evaluating excessive permission vulnerabilities in CameraX pipeline and scoping runtime permission checks.

Reflection:

[2–3 SENTENCES: Principle of least privilege must extend to client hardware permissions. Explicit user consent and scoped hardware access prevent hidden background monitoring vulnerabilities.]

View on GitHub
Case 6 Firestore Security Rules

Cloud Database Misconfiguration

Fixing permissive public read/write access in Firebase Firestore by enforcing role-based rule definitions.

Reflection:

[2–3 SENTENCES: Cloud databases defaulting to open access represent a significant vulnerability vector. Custom Firestore rule validations are essential for verifying user authentication tokens before granting document reads.]
